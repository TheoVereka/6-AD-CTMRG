**对你这个“大周长的 scaling，只保留主导谱”的目标，应该直接用主谱法。上一条把问题扩展到了随机迹估计，没有抓住你的重点。**

我给你的具体方案是：

> **直接用 \(A,B,A,B\rightarrow D,C,D,C\) 做精确 matvec，配合 block Arnoldi／Krylov–Schur，只求前几个到几十个特征值。利用两个 replica 的交换对称性减少存储和运算。整套主谱只算一次，之后计算所有大 \(L\) 的 \(S_2(L)\) 都只是标量运算。**

对 **\(\chi=64\)**，下面的方案可以把主要显存控制在 **25–26 GiB**，在 31 GB 内有余量。**前 8–32 个主导模，我会预留约 2–7 小时作为保守排期；谱分离好时可能不到一小时。** 这个估计的依据和对更大 \(\chi\) 的外推放在最后。

只保留一个必要的物理条件：**要覆盖在目标周长内还没有衰减掉的主导近简并谱簇，包括重数。** 如果它确实只有一两个模，那么一两个特征值当然可以；若常数项或有限周长修正来自一个近简并簇，就把这个簇一起留下。这里完全不需要随机补偿。

## 1. 先统一长度：下面的 \(L\) 就是物理周长

你最初用的是 \(S_2(2L)\)。这次为了和你说的“周长 100、1000”一致，我将公式写成

\[
\boxed{
S_2(L)
\approx
-\ln\!\left[
\sum_{\text{保留的模}}
\lambda_j(T_2)^{L/2}
\right]
+
2\ln\!\left[
\sum_{\text{保留的模}}
\lambda_j(T_1)^{L/2}
\right].
}
\]

也就是说，物理周长 100、1000 分别对应转移矩阵的 50、500 次幂。

这已经说明为什么你的方向合适：**增加周长，不需要增加张量收缩次数。** 求好主谱后，扫描 \(L=100\) 到 \(1000\)，或者更远，都很便宜。

在主特征值为正实数的通常情形，长周长的线性系数直接是

\[
\boxed{
\ln\lambda_1(T_1)-\frac12\ln\lambda_1(T_2).
}
\]

主导簇的重数决定常数项，次主导谱决定有限周长修正。因此只算主谱，已经直接对应你关心的物理量。

下面保留你原来的四个张量名 **\(A,B,C,D\)**。维数一律直接写 **8**，不再给第四个张量改名。`work`、`out` 只是复用的内存缓冲区。

## 2. 分母先算：直接由 \(AB\)、\(DC\) 构造小的 \(T_1\)

先把每个张量的腿排列为

\[
A[a,b,i,p],\quad B[b,c,j,q],\quad
C[b,c,q,j],\quad D[a,b,p,i],
\]

其中：

- \(a,b,c,d\) 都取 \(0,\ldots,7\)；
- \(i,j,k,l,p,q,r,s\) 都取 \(0,\ldots,\chi-1\)。

这只是按照你的四方格连接关系做一次指标排列。

### 第一步：收缩 \(A,B\) 的两条 8 维腿

\[
\boxed{
AB[i,j,p,q]
=
\sum_{a,b}
A[a,b,i,p]B[b,a,j,q].
}
\]

### 第二步：收缩 \(D,C\) 的两条 8 维腿

\[
\boxed{
DC[p,q,i,j]
=
\sum_{a,b}
D[a,b,p,i]C[b,a,q,j].
}
\]

### 第三步：收缩中间两条 \(\chi\) 腿

\[
\boxed{
T_1[(i,j),(k,l)]
=
\sum_{p,q}
DC[p,q,i,j]\,AB[k,l,p,q].
}
\]

这是一个 \(\chi^2\times\chi^2\) 的矩阵。

在 \(\chi=64\) 时，\(AB\)、\(DC\)、\(T_1\) 各占 **256 MiB**，三者合计只有 **0.75 GiB**。先求 \(T_1\) 的前 8–16 个特征值即可，不必求全谱。这部分相对于下面的 \(T_2\) 很便宜。

然后保存需要的本征值，释放这些大缓冲区。

---

## 3. \(T_2v\) 的完整收缩流程：就是下面八步

输入向量排列成

\[
v[i,j,k,l],
\]

共 \(\chi^4\) 个复数。

### 上层：依次收缩 \(A,B,A,B\)

**① 吸收第一个 \(A\)，收缩 \(i\)：**

\[
\boxed{
\mathrm{work}[a,b,p,j,k,l]
=
\sum_i A[a,b,i,p]\,v[i,j,k,l].
}
\]

**② 吸收第一个 \(B\)，收缩 \(b,j\)：**

\[
\boxed{
\mathrm{work}[a,c,p,q,k,l]
=
\sum_{b,j}
B[b,c,j,q]\,
\mathrm{work}[a,b,p,j,k,l].
}
\]

**③ 吸收第二个 \(A\)，收缩 \(c,k\)：**

\[
\boxed{
\mathrm{work}[a,d,p,q,r,l]
=
\sum_{c,k}
A[c,d,k,r]\,
\mathrm{work}[a,c,p,q,k,l].
}
\]

**④ 吸收第二个 \(B\)，闭合 \(a,d,l\)：**

\[
\boxed{
\mathrm{out}[p,q,r,s]
=
\sum_{a,d,l}
B[d,a,l,s]\,
\mathrm{work}[a,d,p,q,r,l].
}
\]

### 下层：依次收缩 \(D,C,D,C\)

**⑤ 吸收第一个 \(D\)，收缩 \(p\)：**

\[
\boxed{
\mathrm{work}[a,b,i,q,r,s]
=
\sum_p
D[a,b,p,i]\,\mathrm{out}[p,q,r,s].
}
\]

**⑥ 吸收第一个 \(C\)，收缩 \(b,q\)：**

\[
\boxed{
\mathrm{work}[a,c,i,j,r,s]
=
\sum_{b,q}
C[b,c,q,j]\,
\mathrm{work}[a,b,i,q,r,s].
}
\]

**⑦ 吸收第二个 \(D\)，收缩 \(c,r\)：**

\[
\boxed{
\mathrm{work}[a,d,i,j,k,s]
=
\sum_{c,r}
D[c,d,r,k]\,
\mathrm{work}[a,c,i,j,r,s].
}
\]

**⑧ 吸收第二个 \(C\)，闭合 \(a,d,s\)：**

\[
\boxed{
(T_2v)[i,j,k,l]
=
\sum_{a,d,s}
C[d,a,s,l]\,
\mathrm{work}[a,d,i,j,k,s].
}
\]

**这八步精确实现你的两个 \(F\) 定义的 \(T_2v\)。** 不形成 \(F\)，不形成 \(T_2\)，不截断 \(A,B,C,D\)。

这里没有额外插入任何复共轭；需要的共轭若已经包含在你提供的 \(A,B,C,D\) 中，就保持原样。

### GPU 上怎样执行这些收缩

最贵的②③⑥⑦，都化成矩阵乘法。例如②：

- 把 \(B\) 排成行指标 \((c,q)\)、列指标 \((b,j)\)；
- 它是一个 \((8\chi)\times(8\chi)\) 矩阵；
- 把 `work` 的 \((b,j)\) 作为收缩维度；
- 其他指标一起当成大量右端列。

在 \(\chi=64\) 时，核心矩阵就是 **\(512\times512\)**，右边有很多列。这适合用大块 complex128 GEMM。

四个原始张量对应的这些矩阵排列预先缓存；不要在每次 matvec 内重复排列它们。

## 4. 关键内存安排：分批第一条输出 \(\chi\) 腿

上面若一次保留所有指标，`work` 有

\[
8^2\chi^4
\]

个复数，在 \(\chi=64\) 时是 16 GiB。

**更合适的安排是：上层将输出指标 \(p\) 每 8 个值作为一批。**

对当前这批 \(p\)：

1. 完成①②③④；
2. 写出对应的 `out[p,:,:,:]`；
3. 复用 `work`，处理下一批 \(p\)。

此时最大的 `work` 只有

\[
16\times 8^2\times 8\times64^3
=
\boxed{2\ \mathrm{GiB}}.
\]

下层完全一样，改成把第一个输出指标 \(i\) 每 8 个值分批。

**这没有增加主要乘加量，也没有张量近似。** 它只是改变循环顺序。

②③中的 `work` 可以通过分块 gather–GEMM–scatter 复用同一块存储：每次取齐当前收缩所需的 \(8\chi\) 个分量，写入独立输出 tile，再写回对应位置。不同的其余指标组互不依赖，不需要复制整个 `work`。

### \(\chi=64\) 的主方案显存预算

| 对象 | 显存 |
|---|---:|
| 80 条完整的 Arnoldi 向量 | 20 GiB |
| `work` | 2 GiB |
| 两个各 1 GiB 的 GEMM tile | 2 GiB |
| 输入、输出、block Arnoldi 临时向量 | 约 1–1.5 GiB |
| \(A,B,C,D\) 及小矩阵 | 远小于 0.1 GiB |
| **主要分配合计** | **约 25–26 GiB** |

31 十进制 GB 约为 28.87 GiB，所以仍有余量。

这个预算要求重启时按块变换 basis，避免额外复制整套 20 GiB 的 Arnoldi 向量。

## 5. 还能更快：利用 replica 交换对称性

这不是额外假设。由两个相同 \(F\) 的定义，\(T_2\) 严格保持

\[
v[i,j,k,l]
\longleftrightarrow
v[k,l,i,j]
\]

的交换对称性。上面的 \(ABAB\) 和 \(DCDC\) 两层也分别保持它。

因此，可以分成

\[
v[i,j,k,l]=+v[k,l,i,j]
\]

和

\[
v[i,j,k,l]=-v[k,l,i,j]
\]

两个扇区。注意：**这里是交换指标，不是复共轭转置。**

这给出两个有用的加速方式。

### 5.1 两个扇区都在求时：一次完整 matvec 推进两条 Arnoldi 递推

把一条对称向量和一条反对称向量相加，存成一条完整向量。

做完一次上面的八步收缩后，分别取

\[
\frac{
(T_2v)[i,j,k,l]
+
(T_2v)[k,l,i,j]
}{2}
\]

和

\[
\frac{
(T_2v)[i,j,k,l]
-
(T_2v)[k,l,i,j]
}{2},
\]

就精确得到两个扇区各自的输出。

然后：

1. 两个扇区分别做 Arnoldi 正交化；
2. 分别归一化；
3. 再相加，作为下一次完整 matvec 的输入。

**这样，80 条完整存储向量，可以同时承载两个扇区各 80 维的递推。**

需要分别维护两个扇区的小投影矩阵和重启变换；不能把相加后的向量直接交给一个完全不区分扇区的普通 Arnoldi 递推。

对于 \(\chi=64\)，这是我建议的起始模式：**用一次昂贵收缩，同时探索两个扇区的主导谱。**

### 5.2 只剩一个扇区时：再减少 38.9% 的乘加

假设当前输入已经是纯对称或纯反对称向量。那么上面的收缩还能精确剪枝。

以 \(ABAB\) 上层为例：

1. 把虚指标 \(a=0,\ldots,7\) 放到最外层逐个处理。
2. 步骤②只计算
   \[
   c=a,\ldots,7.
   \]
3. 把其中 **\(c=a\)** 的那一片乘以 **\(1/2\)**，只乘一次。
4. 步骤③也只对
   \[
   c=a,\ldots,7
   \]
   求和。
5. 步骤④把各个 \(a\) 的贡献累加到 `out`。
6. 全部累加完成后，补回交换伙伴：
   \[
   \boxed{
   \mathrm{out}[p,q,r,s]
   \leftarrow
   \mathrm{out}[p,q,r,s]
   \ \pm\
   \mathrm{out}[r,s,p,q].
   }
   \]

对称扇区取加号，反对称扇区取减号。**最后这一步不再除以 2**，因为虚指标对角项已经在前面除过一次。

随后对 \(DCDC\) 下层做同样的修改。

这个恒等变换的原因是：**交换虚指标 \(a,c\)，对应的输出项恰好是原输出项的 replica 交换，加上该扇区的正负号。** 所以只计算 \(c\ge a\)，另一半由交换精确补回。

原来两层的乘加量是

\[
2304\chi^5.
\]

剪枝后是

\[
\boxed{
1408\chi^5
\quad\text{complex multiply-add},
}
\]

减少了 **38.9%**。

在 \(\chi=64\) 时，固定一个 \(a\)、保留全部 \(p\)，最大的工作张量也正好只有 **2 GiB**。

**我会这样组合这两种模式：两个扇区都活跃时一起推进；一个扇区的主谱已经收敛后，剩余扇区切换到这个更便宜的收缩。**

## 6. 实际的主谱求解流程

### \(\chi=64\)：我建议直接使用这组配置

1. **先求 \(T_1\) 的前 8–16 个特征值。**
2. **用一般复非 Hermitian 的 block Arnoldi／Krylov–Schur 求 \(T_2\) 主谱。**  
   默认不假设 \(T_2\) Hermitian。
3. **起始 block 大小取 4，常驻空间取约 80 条完整向量。**
4. **两个交换扇区分别保留领先模式，但通过上一节的方法同时推进。**
5. **先得到合计约 8 个主导模，随后按需要增加到 16、32 个。**
6. **直接代入第 1 节公式，计算整个目标周长区间。**
7. **一个扇区先完成后，另一个扇区使用剪枝 matvec 继续收敛。**

使用小 block 是为了处理主导簇中的简并。单起始向量在一个精确简并子空间中只能产生一个方向；而你关心的常数项可能恰好依赖这个重数。

如果已经有同一 \(\chi\)、相邻参数点的主导本征向量，就拿它们作起始块，可以省掉不少迭代。

### \(10^{-4}\) 误差需要把特征值算多准？

周长 \(L=1000\) 对应 500 次幂。主特征值相对误差会被这个幂次放大。

因此，**把主特征值求到约 \(10^{-8}\) 的相对稳定程度，已经是合理的目标，不需要 machine precision。** 这给特征值误差和谱截断都留出余量。

谱截断就做一个确定性的检查：

> 把保留数量从 8 增到 16，必要时从 16 增到 32，看目标周长区间中的 \(S_2\) 及其拟合是否在 \(10^{-4}\) 内稳定。

重点检查最短目标周长，因为那里通常需要保留最多的次主导贡献。这个检查没有任何随机补偿。

如果你确实已经进入固定 \(D,\chi\) 下的最终渐近区，往往很快就会稳定。若你正在解析近临界的 \(\ln L\) 等窗口行为，就让保留的近简并谱簇覆盖那个窗口，别事先硬限定只能有两个模。

### \(\chi>64\)：改用单扇区压缩存储

把四指标向量看成一个 \(\chi^2\times\chi^2\) 矩阵：

- 对称扇区只存上三角及对角；
- 反对称扇区只存严格上三角；
- 非对角存储坐标取原元素的 \(\sqrt2\) 倍，以保持普通内积。

这样 basis 存储约减半。每次 matvec 只展开当前一条向量，用两个完整向量缓冲区交替完成上下两层，再压回去。

一组可安排的规模如下：

| \(\chi\) | 单扇区一条压缩向量 | 建议常驻 basis 规模 | 工作张量 |
|---:|---:|---:|---:|
| 64 | 约 0.125 GiB | 160 条左右 | 2 GiB |
| 80 | 约 0.305 GiB | 64 条左右 | 约 1.95 GiB |
| 96 | 约 0.633 GiB | 32 条左右 | 约 1.69 GiB |
| 128 | 约 2 GiB | 8 条左右 | 2 GiB |

这里按单扇区依次求解，收缩使用上一节的剪枝版本。

**\(\chi=128\) 时，真正挤压显存的已是 Arnoldi basis，而非 ABCD 收缩。** 若你前面说的约 460 GB 主机 RAM 仍可用，可以把长 basis 放主机、GPU 分批读入做正交化。例如 80 条完整 \(\chi=128\) 向量占 320 GiB 主机内存，可以保留同时推进两个扇区的较大子空间。此时 PCIe 传输需要计入时间，但可能比用极短子空间反复重启划算。

## 7. 保守总时间估计

先列出这套收缩本身的工作量：

| \(\chi\) | 一次完整 matvec | 一次单扇区剪枝 matvec |
|---:|---:|---:|
| 64 | 19.79 TFLOP | 12.09 TFLOP |
| 80 | 60.40 TFLOP | 36.91 TFLOP |
| 96 | 150.29 TFLOP | 91.84 TFLOP |
| 128 | 633.32 TFLOP | 387.03 TFLOP |

这是按 complex multiply-add 约 8 个实浮点操作计算的。

V100 PCIe 的官方 FP64 峰值为 7 TFLOP/s，因此 \(\chi=64\) 的完整 matvec 算术下限约为 2.83 秒，剪枝版约为 1.73 秒。实际显然要加上 GEMM 效率、数据排列和正交化开销。[images.nvidia.com](https://images.nvidia.com/content/technologies/volta/pdf/tesla-volta-v100-datasheet-letter-fnl-web.pdf?utm_source=chatgpt.com)

**用于保守排期，我采用：**

- \(\chi=64\) 完整 matvec：**20 秒/次**；
- \(\chi=64\) 单扇区剪枝 matvec：**15 秒/次**；
- 总时间再加约 **20% 余量**。

这些是未实测的预算假设，不是硬件 benchmark。

### \(\chi=64\)，两个扇区一起推进

| 完整 matvec 调用次数 | 含余量的总预算 |
|---:|---:|
| 100 次 | 约 40 分钟 |
| 300 次 | 约 2 小时 |
| 1000 次 | 约 6 小时 40 分钟 |

因此，**对前 8–32 个主导模，我会先按 2–7 小时预留时间。** 谱簇分离良好时可能更快；若主导谱极密，迭代次数也可能超过这个预算。单凭 \(D,\chi,L\) 无法给出未知谱的迭代次数上界。

### 更大 \(\chi\) 的时间增长

在迭代次数相近时，主要工作量按

\[
\boxed{
\left(\frac{\chi}{64}\right)^5
}
\]

增长。用同样的 300 次完整 matvec 工作量作比较：

| \(\chi\) | 相对工作量 | 同效率、同迭代数的预算 |
|---:|---:|---:|
| 64 | 1 | 约 2 小时 |
| 80 | 3.05 | 约 6 小时 |
| 96 | 7.59 | 约 15 小时 |
| 128 | 32 | 约 64 小时 |

更大 \(\chi\) 时，basis 容量或主机串流还可能改变迭代效率，所以不能把“\(\chi\ge64\)”理解成一个统一的运行时间。

**如果实际参数就是 \(D=8,\chi=64\)，我的执行选择是：80 条完整向量、两个交换扇区同时做 block Arnoldi、先取 8 个主导模再按需到 16/32；一边收敛后切换单扇区剪枝。** 这保留了 ABCD 收缩的全部结构，显存在 31 GB 内，误差目标按 \(10^{-4}\) 的 \(S_2\) 来设。主谱求完后，你关心的整段大周长 scaling 都直接从同一组特征值得到。
