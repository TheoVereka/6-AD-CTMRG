## 已通过的对象与本次失败的对象

四个 edge 的配对与排列、显式 T₁、T₂ 八步 matvec、replica 对易/投影，以及完整谱到 S₂ 的公式，已通过独立小矩阵检查；参见 [核心检查](verify_renyi2_core.json) 与 [三 pair CLI 检查](verify_renyi2_cli.json)。此前 modes=2→4 或 4→8 的部分小例子成功，不代表默认配置可靠。

本次发现：真实 CTM 缓存输入在默认 `modes=8,16,32` 下，**第一阶段8模即失败**。问题出现在迭代求谱层；不能把它当作 edge indexing 或 replica 收缩被证伪，也不能把失败返回的 Ritz 根当作真实特征值。

## 可复现配置

输入是 D=2、χ=4、pair1 的 float64 canonical edge 缓存 [tiny_checkpoint_pair1_edges.npz](tiny_checkpoint_pair1_edges.npz)。参数为 real float64、block_size=4、subspace=80、eig_tol=1e−10、max_matvec=800、batch=8、seed=20261009。CLI 的 L 数切口键，取100到1000、步长100。

```powershell
python -B src_code/scripts/renyi2_twoc3.py --edge-file tmp_tee_schematic_20261009/algorithm_checks/tiny_checkpoint_pair1_edges.npz --pair 1 --subspace 80 --max-matvec 800 --L-min 100 --L-max 1000 --L-step 100 --threads 2 --output tmp_tee_schematic_20261009/algorithm_checks/cli_default_modes_test.json
```

这里没有指定 `--modes`，使用脚本默认8、16、32。以上只是记录复现命令；本次停止后没有再次运行。

## 已观测结果

原生 Python 退出码为 **2**，报告 `status=eigensolver_not_converged`，未输出 S₂。

| 对象 | 原因/步数 | 具体失败证据 |
|---|---|---|
| T₁ | `full_space_reduction`，16 matvec | 第8根约 −3.38e−10，相对残差约7.54e−8，未达到1e−10 |
| T₂，+交换扇区 | `max_matvec_reached`，800 matvec，10次重启 | 返回假主根约2.104972，残差约0.989；basis正交误差353.33 |
| T₂，−交换扇区 | `max_matvec_reached`，800 matvec，12次重启 | 返回根约2.3052e−4，残差约0.976；basis正交误差300.70 |

正交误差为求谱器报告的 `||QᵀQ−I||`。它已显著崩坏，不能仅放宽小根相对残差阈值后宣称问题解决。

用同一组归一化 edge 独立构造的完整稠密 T₂，其真实谱半径约为 **0.0132145875**；迭代返回的2.104972不是有效主根。稠密 T₁ 的主根约为0.1150327157。

T₁ 还单独暴露了小根残差尺度的问题：当 `||Ax||+|λ|||x||` 很小时，要求所有小根达到同一个严格相对阈值可能不切实际。当时T₂仅定位到扩展/重启后的 basis 正交失稳；本轮后续诊断已进一步定位到首次restart之前接纳近breakdown块的过程，详见顶部更新。求谱算法尚未实施修复。
