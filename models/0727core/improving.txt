我审查后，真正值得优先改的主要有下面这些。按预期收益排序。

## 1. 能量计算仍然把 C3 等价的 3 个 bond 分别计算

位置大致在三个 energy 函数：

* `energy_expectation_nearest_neighbor_3ebadcf_bonds`
* `energy_expectation_nearest_neighbor_3afcbed_bonds`
* `energy_expectation_nearest_neighbor_other_3_bonds`

每个 environment 当前计算：

* 6 个 NN density matrix
* 6 个 NNN density matrix

但在当前 C3 ansatz 与 C3 CTM 下，每组三个旋转相关的 bond 完全相等。例如 env1：

```text
AD = CF = EB
FA = DE = BC
AE = EC = CA
DB = BF = FD
```

env2、env3 也各自存在完全相同的四组三元轨道。

因此每个 environment 实际只需要计算：

```text
2 个 NN representative
2 个 NNN representative
```

然后用对应三个 coupling 的和乘上 representative energy。即使将来三个 coupling 不完全相等，也可以使用：

```text
(J1 + J2 + J3) * E_representative
```

不必要求三个 coupling 数值相同。

### 收益

* 每个 environment：12 次大 rho contraction → 4 次
* 三个 environment：36 次 → 12 次
* energy forward 理论上接近 **3 倍加速**
* checkpoint backward 中的重计算也同时减少约 3 倍
* `_CACHE_RHOS` 中同一轨道的三个 rho 可以直接引用或复制同一个小 rho

这是整个文件中最明确、收益最大的 C3 优化。

---

## 2. 每个 environment 仍然构造 6 个 open tensor 和 6 个 closed tensor，但实际上只有 2 个不同

位置：

```text
build_open_closed_env1
build_open_closed_env2
build_open_closed_env3
```

以及三个 energy 函数中的 lazy-open 路径。

对于当前允许的所有 C3 ansatz，经过这些函数规定的 canonical index ordering 后：

```text
open_A = open_C = open_E
open_B = open_D = open_F

closed_A = closed_C = closed_E
closed_B = closed_D = closed_F
```

我用 `c3vypi`、`twoc3`、`c6ypi` 和 `neel` 检查过，前三者逐元素完全相等，`neel` 的误差在约 (10^{-17}) 的舍入范围内。

所以每个 environment 只需要构造：

```text
open_even / open_ACE
open_odd  / open_BDF

closed_even
closed_odd
```

其他 site 名称直接映射到这两个 representative。

### 收益

open tensor 大小为：

[
(\chi D^2)^2d^2
]

以 float64、(d=2) 为例：

* (D=8,\chi=80)：一个 open 约 0.78 GiB
  当前六个约 4.7 GiB，改成两个约 1.6 GiB。
* 更大的 (D,\chi) 下差异会非常夸张。

因此：

* pre-build 路径的 open/closed 构造成本约减少到原来的三分之一
* 六个 open 同时驻留变为两个
* 六个 closed 矩阵变为两个
* 很多目前被迫走 lazy 路径的尺寸，改后可能可以安全使用更快的 pre-build 路径

这一项最好与上一项一起修改。

## 3. lazy energy 路径为了得到 closed tensor，先完整构造 open tensor再 trace

例如：

```python
_open_E = ...  # shape (N,N,d,d)
closed_E = oe.contract("MXii->MX", _open_E)
del _open_E
```

三个 energy 函数的 lazy 分支都重复了这种模式。

如果目标只是 closed tensor，就不应该先生成带两个开放 physical indices 的：

[
N\times N\times d\times d
]

张量。应在原始 contraction 中直接收缩物理指标，输出 (N\times N) closed tensor。

### 优化理由

当前每个 environment 在真正计算 bond 之前，先额外构造六个完整 open tensor，仅用于 trace 后立即删除。

这意味着 lazy forward 中：

* 6 次昂贵的 open construction 完全没有必要
* 每次临时显存是 closed tensor 的 (d^2) 倍
* autograd 还需要保留这些 closed tensor 构造对应的反向信息

即使尚未实现“6 个 site 缩为 2 个 representative”，直接 closed contraction 也通常能令 lazy energy 部分减少明显的时间和峰值显存。

若同时应用第 2 项，则只需直接构造两个 closed representative。

## 4. `trunc_rhoC3` 显式构造并同时保存 `C²` 和 `C³`

当前：

```python
R1 = matC.T
R2 = matC @ matC
M  = R1 @ R2.T
```

实际上：

[
M=(C^T)^3.
]

令：

[
N=\chi D^2,
]

那么 `matC`、`R2` 和 `M` 都是 (N\times N) 大矩阵。当前 `R2` 会一直活到 SVD 完成并构造 `P_out` 为止。

以 float64 为例：

* (D=8,\chi=80)，(N=5120)：每个矩阵约 200 MiB
* (D=10,\chi=140)，(N=14000)：每个矩阵约 1.46 GiB

因此仅：

```text
matC + R2 + M
```

就可能占约 4.4 GiB，complex128 时再翻倍。

### 最强优化：matrix-free randomized SVD

rSVD 实际不需要显式得到整个 (M)，只需要：

```text
M @ X
Mᴴ @ X
```

而：

[
M X=(C^T)(C^T)(C^T X)
]

可以通过三次 skinny matrix multiplication 完成。

这样能够：

* 完全不创建 `R2`
* 完全不创建 `M`
* 避免两次 (O(N^3)) 的 full matrix cube GEMM
* 改为若干次 (O(N^2\chi)) skinny GEMM
* projector truncation 很可能得到数量级级别的加速

但需要把 SVD autograd 直接写成以 `matC` 为输入的 linear-operator 版本，正确处理由 (dL/dM) 到 (dL/dC) 的链式梯度。

### 较容易的保守优化

若暂时不想改 SVD backward，至少不要让 `R2` 穿过整个 SVD 生命周期。

可以：

1. 用临时矩阵构造 `M`
2. 立即释放临时矩阵
3. SVD 完成后直接按因子形式计算：

[
P_{\rm out}
===========

C^T\left[C^T\left(VS^{-1/2}\right)\right]
]

而不是保存：

```python
R2 = C @ C
P_out = R2.T @ (...)
```

这会增加一次 (N^2\chi) skinny GEMM，但减少一个长期驻留的 (N^2) 矩阵；相对于两次 (N^3) cube GEMM，这个额外成本通常很小。

### 一个重要限制

仅仅因为 C3 对称，不能一般性地把：

```text
SVD(C³)
```

直接替换成：

```text
SVD(C)
```

非正规、非 Hermitian 的矩阵中，两者的 singular subspace 不相同。只有你另外强制 corner 为 Hermitian/PSD 或采用不同的 truncation 定义时，才能这样简化。

## 5. 记录 truncation error 时完全没有必要执行 full SVD

`trunc_rhoC3` 中：

```python
if _RECORD_TRUNC_ERROR:
    torch.linalg.svd(M, full_matrices=False)
```

这会为了记录 discarded singular weight，对整个 (N\times N) 矩阵做 full SVD。

但 truncation error 本身已经定义为：

[
\epsilon_{\rm trunc}
====================

\frac{
\sqrt{|M|*F^2-\sum*{i=1}^{\chi}S_i^2}
}{
|M|_F
}.
]

因此只需要：

* 正常 partial/rSVD 得到保留的前 (\chi) 个 singular values
* 计算一次 (|M|_F)

完全不需要所有 discarded singular values。

### 收益

clean evaluation 时可从：

* full (O(N^3)) SVD
* 大量额外 SVD workspace

变为：

* 原本就要执行的 partial SVD
* 一个 (O(N^2)) Frobenius norm reduction

大 (D,\chi) 时差异极大。这属于完全可以删除的计算。

若之后采用 matrix-free (M)，可以再研究如何不显式形成 (M) 地估计 Frobenius norm；但即便继续保存 (M)，移除 full SVD 已经很有价值。

## 6. `CTM_CONV_MODE='both'` 时，SV 尚未收敛前的 energy proxy 全部无用

当前 `CTMRG_from_init_to_stop` 中逻辑是：

```python
if effective_mode == 'both':
    sv_met = sv_met or bool(cv)

if energy_proxy_fn is not None:
    curr_e = energy_proxy_fn(...)
```

也就是说，即使：

```text
sv_met == False
```

仍然每一轮计算 energy proxy。

但 `both` 模式的退出条件必须同时满足：

```text
sv_met and e_met
```

因此 SV 尚未收敛时，energy proxy 不可能导致停止；这些调用在逻辑上完全无用。

而 energy proxy 通常需要构造多个 open tensor，成本可能接近很大一部分完整 energy evaluation。

### 应当做的逻辑

在 `both` 模式中：

```text
SV 未达到阈值：
    不计算 energy proxy

SV 第一次达到阈值后：
    开始记录并比较 energy proxy
```

也可以在 SV 接近阈值后每隔 2–5 轮计算一次，而非每轮计算。

### 收益

clean evaluation 中，如果 CTMRG 需要二三十轮而 SV 在后期才收敛，可以省掉前面大多数 proxy contraction。实际加速可能远高于 10%。

## 7. contraction-based CTM initialization 会构造极大的 (D^8) 和 (D^{10}) 中间张量

`initialize_envCTs_C3(identity_init=False)` 中：

```text
BC2323
DE3131
FA1212
```

每个大小为：

[
D_{\rm squared}^4=D^8.
]

更加严重的是：

```text
TB_raw
TA_raw
```

大小为：

[
D_{\rm squared}^5=D^{10}.
]

随后它们才与 projector contraction，将大多数维度截断到 (\chi)。

例如 (D=6)：

[
36^5 \approx 6.0\times10^7
]

一个 `TB_raw` 在 float64 下约 0.45 GiB，两个接近 0.9 GiB，还不包括其他中间量和 autograd。

### 优化方式

* 如果实际一直使用 `identity_init=True`，可以直接删除整个 contraction initialization 分支。
* 如果仍需保留，projector 应直接进入 `TB`、`TA` 的原始 tensor-network contraction，不要先生成 `TB_raw`/`TA_raw`。
* `BC2323`、`DE3131`、`FA1212` 也应尽量与后续 contraction 融合，不单独物化三个 (D^8) tensor。

这项主要影响初始化峰值显存和启动时间，不影响每一轮 CTMRG；但一旦启用 contraction initialization，峰值非常大。

## 8. 小 (D) 时当前 randomized SVD 可能比 full SVD 更慢

当前设置：

```python
q_over = 2 * chi
```

而：

[
N=\chi D^2,\qquad \frac{q}{N}=\frac{2}{D^2}.
]

所以：

* (D=2)：(q=N/2)
* (D=3)：(q\approx0.22N)

同时 adaptive 设置在小 (D) 使用 4 次 power iteration。一次 rSVD 需要：

* 初始 `A @ Rand`
* 每次 power iteration 两个大矩阵乘法
* 多次 QR
* 对较宽的 projected matrix 做 SVD

在 (D=2) 时，这很可能比直接 full SVD 做更多工作。

### 优化理由

应根据 `q/N`、矩阵尺寸和设备动态选择：

```text
q/N 较大或 N 较小时：full SVD
q/N 较小且 N 大时：rSVD
```

不要在所有 (D) 上统一使用 rSVD。

另外，当前 full-SVD 分支在 CUDA 上无条件：

```python
A.detach().cpu()
CPU SVD
结果复制回 GPU
```

这对小矩阵可能合理，但对较大的 GPU 矩阵可能产生严重 PCIe 和 CPU LAPACK 开销。应恢复真正的尺寸阈值或按硬件 benchmark 决定，而不是始终 CPU offload。

## 9. `check_env_CV_C3` 中 `now_rho` 的 singular values 被重复计算

当前每个 environment：

1. 构造 `lastC³`
2. 构造 `nowC³`
3. `svdvals(lastC³)`
4. `svdvals(nowC³)`
5. 后面的 collapse guard 再次执行 `svdvals(nowC³)`

因此每轮 convergence check 共执行：

* 6 次 corner cube
* 9 次 (\chi\times\chi) SVD

其中三个 `now_rho` SVD 是完全重复的，可以直接复用第一次得到的 `sv_now`。

此外，若你不坚持旧的 one-cut `C³` convergence criterion，可以直接比较 corner 自身的 normalized singular spectrum，省掉所有 `C³` matrix multiplication。这样会改变 convergence metric，但不会改变 CTMRG projector。

### 收益范围

这项不会影响大 (D) 下的主要峰值显存，因为矩阵只有 (\chi\times\chi)。但在 (D=2) 或很小的 CTMRG 中，convergence check 相对 update 成本较高，可能产生明显加速。大 (D) 时优先级低于前八项。
